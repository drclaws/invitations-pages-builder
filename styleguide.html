Design system

A showcase of the design tokens and components of the invitation pages. The token values are the default theme: to restyle the pages, change the token values, and every component here follows.

Tokens

The script reads the list straight from /assets/app.css: :root rules → --* properties. The values are the computed ones (getComputedStyle), so the table shows what actually applies at the current width and is recalculated when the window is resized. The “mobile/desktop” badge marks derived tokens that have separate reference values for the two device classes. For tokens written in rem or em, both the original value and the pixels are shown; the full formula is in the tooltip of the value.

Font size check

The page follows the user’s font size: fonts, container widths and icons are set in rem, spacing in rem capped by the window width, and the layout thresholds of components in rem, measured against the container width. The buttons above (they need the script) change the font size of the root element of this page, just as the system setting on a phone does. Check at a width of 360 px at 150 % and 200 %: no horizontal scroll, the countdown folds into 2×2, the labels stay inside their cells. 330 % is the limit of the system “Larger Text” setting on an iPhone (root ≈ 53 px): the countdown becomes a single column, and there is still no scroll. The layout breakpoint --bp-layout is set in em in a media query and depends on the font size in the browser settings, not on the root element: check it with the browser’s “Font size” setting — at “Very large”, the two columns switch on at a wider window.

The script reports the viewport width.

The script builds the token table, so it is not shown without JavaScript — this is the only part of the showcase that needs the script. The components, states and type scale below are visible without it; the token values can be read in /assets/app.css, section “1. Tokens”.

Layout

One container in two widths, one grid, one vertical rhythm and one media frame with fixed proportions. At the layout breakpoint (48em — 768 px at the default font size) only the layout tokens are overridden: the number of columns and the image proportions; the visual style of the components stays the same.

The cover height is set by the token --cover-min-height: the share --cover-height-ratio (separate for mobile and desktop) of --viewport-height (100svh with a fallback to 100vh). Media and the video tile are no taller than --media-max-height, so in landscape orientation on a phone the frame fits the screen.

Gallery: .gallery / .gallery__item (plates in place of photos)

The repository has no media files, so the gallery items are shown as plates. On real images, .gallery__item sets the proportion --ratio-gallery, object-fit: cover and the focal point --image-focus.

Cover photo: .cover__backdrop, .cover__photo (plates in place of photos)

The optional photo behind the cover (the background field) sits in the backdrop .cover__backdrop under the content and fills the cover at any screen proportion (object-fit: cover). Over the photo lies a veil of the colour --color-cover-veil at the opacity --cover-veil-opacity, and all the cover text on the photo is in --color-cover-text; there is no secondary grey on the photo. The veil is chosen for the worst frame, a black one: the text contrast is at least 4.5:1 on any photo (the calculation is in the comment next to the token). The photo is decorative: alt="", the backdrop is hidden from screen readers, and the photo is left out of print. Here plates stand in for the photo: a light one and a dark one.

Which part of the frame stays visible when the screen crops the photo is set by a modifier from the backgroundFocus list: .cover__photo--center (the default), --top, --bottom, --left, --right, --top-left, --top-right, --bottom-left, --bottom-right — the object-position keywords. A portrait screen crops a landscape frame on the left and the right, a wide one at the top and the bottom. Check the focus on the built page of the main example.

Media tile: .media-tile, .media-tile--video (plates in place of posters)

Photos and videos on the page are the same tiles: a link to the file (.gallery__link.media-tile), the picture fills the frame, and the focus ring is inside the frame. A video has a round ▶ badge over the poster (.media-tile__badge, with the inline SVG .media-tile__icon in currentColor inside): diameter --media-play-size, triangle --media-play-icon-size, colours from the overlay roles (--color-overlay-control, under the pointer --color-overlay-control-hover, --color-on-overlay). The whole tile is pressable; the badge only shows that it is a video. .media-tile__duration is the duration in the corner, shown when the length of the video is known. In order: photo, video, video under the pointer, video in focus, video with a duration.

Single tile: .gallery--single (portrait frame 9 / 16)

A single tile in the centre of the column, in the proportion of its frame. The size comes from an invisible sizer before the tile: <svg class="gallery__sizer"> with the size of the video from the data in width/height/viewBox, or, without them, .gallery__sizer--default with the proportion --ratio-video. The markup has no style attribute. The tile is no taller than --media-max-height and no wider than the column, so a portrait video on the desktop stays a narrow tile in the centre.

Video in the viewer: .lightbox.is-video, .lightbox__video

Pressing a video tile opens the same viewer as for photos and starts the video at once, with sound. The viewer holds a single <video controls> with the browser’s native panel: its look, buttons, seeking and full-screen mode (on an iPhone, the system player) come from the browser; the panel has no styles or tokens of its own. The frame fits the viewer whole, in the proportion of the video. A video reached by swiping does not start by itself and loads nothing until it is pressed; it stops when the viewer moves away from it or closes. In full-screen mode, Esc first leaves it, and a second Esc closes the viewer. If the file fails to load, a message replaces the frame (.lightbox.is-error). The script creates the viewer and the repository has no media files, so there is only a description here; check it on a built page with a video. Without the script the tile is a plain link: the browser opens the video in its own player.

A section of widgets: .section--start | --center, .container--narrow | --wide, .section__body, .section__note

The frame of every ordinary section of the page: an h2 heading (h3 here, inside a showcase section) and the body — widgets one after another with a gap of --space-lg, ending with the guest’s note (.card.section__note, no wider than the text column). The width and alignment come from the configuration. The heading can be hidden (.visually-hidden): it stays the accessible name of the section. There is one reveal mark per section, on the container. In order: narrow, left-aligned, with a note; wide, centred; a hidden heading; a section of a single note.

Top bar — the collapsed cover: .cover-bar, .cover-bar__title, __sep, __date

On scroll the cover collapses into a bar at the top edge of the window: the cover text and photo fade out and the bar fades in — only opacity changes, following the progress --cover-progress (the shares --cover-fade-end and --cover-bar-fade-start). The bar holds a single line, “names · date”, with no caption above the names; pressing it does nothing. Its height is --cover-bar-block-size: a --text-base line with the padding --cover-bar-padding-block, but no less than --tap-min, plus the safe area at the top; it grows with the font size (the font size buttons at the start of the showcase: 150 % and 200 %). Names that do not fit are cut with an ellipsis; the date and the separator are not. The layer is --z-sticky: above the page, below the viewer. Here the bar is shown collapsed, without the data-cover-bar hook: on the page the bar with the hook is visible only under the cover-bar-on marker, which the script sets; without the script there is no bar. Check the collapsing itself on a built page.

The fill above the bar: .cover-bar::before

Safari on iOS 26 also paints the page above the window — under the translucent status bar — while the stuck bar sits below that strip. The bar extends upwards in its own colour by the height of the screen (--viewport-height), so the scrolled content is not visible in the strip. Here the frame clips the fill: the upper hatched strip is page content above the bar, and it is covered; the lower one is content below the bar, and it is visible. The fill is part of the bar: it appears and fades with it, catches no presses, takes no space in the flow and is left out of print.

States

The states are the same on mobile and desktop. Hover applies only where there is a real pointer (@media (hover: hover)); keyboard focus is always visible. Below, the states are shown statically with the demo classes .is-hover, .is-focus and .is-active: they are listed next to the real :hover, :focus-visible and :active and set no values of their own.

Primary button: .btn.btn--primary

Secondary button: .btn.btn--secondary

ordinary Link button :hover Link button :focus-visible Link button :active Link button aria-disabled Link button

A disabled link button is output without href (role="link" aria-disabled="true"): CSS blocks only the pointer, and a link with an address would still work from the keyboard.

Over the overlay: .on-overlay and the lightbox elements (.lightbox__counter, .lightbox__button)

Inside .on-overlay the text and focus ring roles take the values for the dark backdrop of the lightbox; the components themselves are not rewritten. The lightbox buttons carry their own backdrop, --color-overlay-control, because the arrows lie over the photo. The page script creates the window itself (.lightbox). In order: ordinary, hover, focus, disabled (the end of the gallery).
